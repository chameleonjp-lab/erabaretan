# 選ばれたん：P4-03 バランス検証 H2

- 文書状態：自動採用門通過・正式v2採用保留
- 対象：alpha-12の実験プロファイル `candidate.p4-03.h2`
- ベースコミット：`3462375940f2850dd9a72a3c1fbda2375d4e18be`
- レビュー：Sol・Highの設計承認済み。正式採用には人間試遊と独立最終レビューが必要

## 1. 位置付け

P4-02で固定した`public-greedy-v1` CPU対CPU指標を基準に、P4-03の単一数値変更を検証する。H2は正式な`ruleset.alpha-12.v2`ではない。V1のカード定義・ruleset・既定シミュレーションは上書きせず、別catalog/profileで実行する。

H1「星砕きのプレイヤー損傷16→14」は先行検証で棄却した。平均ラウンド6.2490、最大ラウンド到達15.0391%、75到達16.4063%で、採用門（75到達がベース比+5ポイント以上または20%以上、最大ラウンド15%以下）を満たさなかった。H1のコードは本実験へ持ち込まない。

## 2. H2仮説と変更範囲

変更は`attack.star-breaker.v1`のRELEASE効果にある`DAMAGE_WORLD.amount`だけである。

```text
V1：プレイヤー損傷16、世界損傷7
H2：プレイヤー損傷16、世界損傷8
```

次は変更していない。

- CPU方針`public-greedy-v1`
- 星砕きのRESTRAIN（次の攻撃への盾3）
- 他11種類のカード、条件、複製枚数、カードID
- HP、世界耐久、境界75・50・25、最大10ラウンド
- 世界損傷の採点係数`-3`、世界律、終端・審定処理
- UI、通信、P5要素

世界83から解放した局面では、V1は76で境界未到達、H2は75で境界到達となる。この差は自動試験で固定した。世界損傷が1増えるため、星砕き1回ごとに世界損傷責任と、その責任に由来する神の評価減点が最大3増える。これは採点係数の変更ではなく、カード変更から生じる意図した副作用である。

## 3. CPUバイアスとの分離

V1とH2は同じ`public-greedy-v1`を使い、候補の評価点へカード効果量を渡さない。1024件すべてで、論理的な山札順・初期手札・先攻が一致した。したがって、星砕きの選択そのものは同じ初期入力から始まり、75到達率の変化は世界損傷量の機械的な差と、その後の公開世界耐久による二次的フィードバックとして分類する。

解放率や抑制率、カード使用数はそのフィードバックを記録する参考値であり、CPU方針の改善を意味しない。

## 4. 測定条件

- seed corpus：`hex32-seed-1-to-1024`
- seed：`00000000000000000000000000000001`〜`00000000000000000000000000000400`
- 件数：1024
- match ID prefix：`p4-03-h2-gate`
- CPU：`public-greedy-v1`
- 最大ステップ：既定4096
- 同一入力を2回実行し、完全一致を確認
- V1とH2の配札・先攻一致をseedごとに確認

機械可読スナップショット：

- `tests/fixtures/p4-03-h2/p4-03-h2-v1-baseline.json`
- `tests/fixtures/p4-03-h2/p4-03-h2-candidate.json`

各snapshotにはbase commit、corpus、profile、集計値、分母、seedごとの最終状態ハッシュ、終了種別、75・50・25到達、完了ラウンド、最大ラウンド到達を含める。H2はprofile識別子を状態へ含めるため、V1とH2の最終ハッシュ文字列が異なること自体は不具合ではない。V1のハッシュ不変性はV1 baseline snapshotと再実行一致で判定する。

## 6. 自動試験

`tests/content/p4-03-balance-pass.test.mjs`で次を固定した。

- V1/H2のカード効果差分が世界損傷7→8だけであること
- プレイヤー損傷16、盾3、他のruleset値が不変であること
- 世界83からV1は76、H2は75となり、H2だけ75境界を通過すること
- V1/H2の同一seed再実行が完全一致すること
- 1024件のV1 metrics・最終状態ハッシュ列がbaseline snapshotと一致すること
- 1024件のH2 metrics・最終状態ハッシュ列がcandidate snapshotと一致すること
- 配札、初期手札、先攻が1024件すべて一致すること
- 正常終了、`INVALID_MATCH=0`、`SERVER_ABORT=0`
- P4-02bの最大ラウンド`TURN_START`終端が候補プロファイルでも余分な行動を許さないこと

## 7. 人間プレイ確認

自動門通過後の次の停止条件。現時点では未実施であり、正式v2化を宣言しない。

- 固定場面：世界83で星砕きを解放または抑制し、75境界の差を比較
- 完全試合：最低8試合。seedと先攻を記録
- 各試合後に次を記録する

  - 星砕きの解放が依然として魅力的か
  - 抑制が自動的な正解になっていないか
  - 境界直前の停滞が常態化していないか
  - 選定結果をある程度予想できるか

## 8. 現時点の判断

H2は「実験プロファイルとして人間試遊へ進める」段階まで採用する。`ruleset.alpha-12.v2`や`attack.star-breaker.v2`への昇格、現行V1の置換、P5への移行は、人間プレイ記録とSol・Highの独立最終レビューが完了するまで行わない。
