## 1. 目的

P3-04では、試合終了後に「何が起きたか」と「神がどう審定したか」を分けて表示する。

正式な戦闘結果・採点・神の選定は、終了した`GameState`を`game-core`の`summarizeMatch`で検証して得る。転換点は、各コマンドの実行結果に含まれるイベントから、公開してよい事実だけを画面セッション内で抽出して合成する。

```text
final GameState
  └─ summarizeMatch(state)
       ├─ 戦闘勝者
       ├─ 神の選定者
       └─ 正式な点数内訳

公開イベントのコマンド別バッチ
  └─ collectPublicFactBatch(events)
       └─ composeResultJudgment(summary, batches)
            └─ 最大3件の転換点
```

イベントだけから正式採点を再計算しない。`GameState`へ恒久的なイベントログを追加せず、状態ハッシュの形式も変更しない。

## 2. 結果画面の順序

次の順序を固定する。

1. 試合終了と終了理由
2. 戦闘勝者
3. 神の審定
4. 生存評価・世界評価・合計点
5. 試合を変えた最大3件
6. 神の選定者
7. 再戦

通常終了では、神の選定を次の要素の合計として説明する。

- 生存評価
- 世界損傷責任
- 有効世界再生
- 破界責任

「世界を守ったから選ばれた」のような単一原因の断定は表示しない。

降参、切断敗北、サーバー中断、無効試合では、正式点数と神の選定を付与しない。結果画面ではその事実を明示する。

## 3. 公開事実イベント

次のイベントだけを結果要約用の事実へ変換する。

| 実行イベント | 公開事実 | 表示に使う値 |
|---|---|---|
| `DAMAGE_WORLD_APPLIED` | `WORLD_DAMAGED` | 責任者、実効損傷 |
| `RESTORE_WORLD_APPLIED` | `WORLD_RESTORED` | 実効再生者、実効再生 |
| `WORLD_THRESHOLD_TRIGGERED` | `WORLD_THRESHOLD_CROSSED` | 境界値 |
| `DAMAGE_PLAYER_APPLIED` | `PLAYER_DAMAGED` | 実効損傷 |
| `PAY_HP_APPLIED` | `HP_PAID` | 支払者、支払量 |
| `PLAYER_DEFEATED` | `PLAYER_DEFEATED` | 対象者 |
| `WORLD_COLLAPSED` | `WORLD_COLLAPSED` | 終了事実 |
| `MATCH_FINISHED` | `MATCH_FINISHED` | 終了事実 |

カードID、`effectId`、コマンド履歴、手札、山札順、ドローしたカード、seed、乱数消費数、防御カードの所持有無は結果要約へ渡さない。

イベントは1コマンド1バッチとしてまとめる。同じ行動で発生した世界損傷、境界通過、撃破、世界崩壊を複数の転換点として重複表示しない。

## 4. 転換点の抽出

候補を次の順で作る。

1. 撃破または世界崩壊を起こした決着バッチ
2. 決着バッチを除く最大の実効世界損傷バッチ
3. まだ選ばれていない最大の実効世界再生バッチ
4. まだ選ばれていない境界通過バッチ
5. イベントが保持されない場合の最終状態による終了事実（最大ラウンド、降参など）

最大3バッチだけを採用し、表示時は発生順へ戻す。

代表的な表示例：

- 「守護者Aが世界へ7損傷を与えました。」
- 「守護者Bが世界を7回復しました。」
- 「守護者Aの世界への10損傷を契機に、世界耐久が0となり、世界が崩壊しました。」
- 「世界が75・50境界を通過しました。」

転換点がない場合は「大きな公開転換点は記録されませんでした」と表示する。これは秘密情報から推測した補完を行わないための明示である。

## 5. 完了条件

- 結果画面が正式な`summarizeMatch`を使用する
- 通常終了で生存評価・世界評価・合計点を表示する
- 非通常終了で点数・神の選定を付与しない
- 最大3件、同一バッチの重複なし、発生順で表示する
- 最大世界損傷と最大有効世界再生を抽出できる
- 撃破と世界崩壊の同時発生を1つの決着転換点へまとめる
- イベントがない最大ラウンド・降参を最終状態から説明できる
- malformed eventを無視し、結果画面を壊さない
- 結果要約に手札、山札順、カードID、effectId、seed、command履歴を含めない
- 再戦時に前試合の公開事実バッチを破棄する
- TypeScript型検査、静的Webビルド、既存試験、P3-04試験が通る
