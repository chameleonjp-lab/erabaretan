# 選ばれたん：ゲームプロダクトマネージャーレビュー

- 文書状態：レビュー完了・次工程へ反映待ち
- 更新日：2026-08-13
- 対象：`00_CURRENT_PLAN.md`、`04_GAME_PRODUCT_PLAN_V2.md`、`03_PRODUCER_REVIEW.md`

## 1. 結論

企画の中心は維持してよい。

特に、

- 戦闘勝者と神の選定者を分ける
- 世界を壊すほど戦闘上は有利になり得る
- 世界を守る行動には戦闘上の代償がある
- 世界への責任を結果だけでなく試合中の世界律へ返す

という四点は、本作を他の短時間カード対戦から分ける中心として成立している。

一方で、現行計画は「ゲームとして何を作るか」はかなり具体的だが、「最初の利用者がどこで離脱するか」「どの段階を公開候補とするか」「数値目標を何で判断するか」がまだ弱い。

したがって、実装前に企画を大きく増やす必要はない。次に必要なのは、初回体験と公開判断を測定可能な形へ変えることである。

## 2. 最優先の指摘

### 2.1 7分は目標値であり、まだ成立条件ではない

現行計画では6〜9分、紹介文では約7分としている。

しかし、1対1、最大10ラウンド、通常行動18秒、防御判断10秒に加え、カード選択、解放・抑制、世界律、演出、結果確認まで含めると、7分へ収まるかは未証明である。

このため「7分」を固定仕様ではなく、試遊で検証する商品目標とする。

初期試作では次を記録する。

- 試合開始から決着までの中央値
- 90%の試合が終わる時間
- 自分の操作待ち時間
- 相手待ち時間
- 演出だけに使った時間

公開候補では、中央値5〜8分、90%が10分以内を暫定目標とする。

### 2.2 最初の一戦までが長い危険がある

本作には、世界耐久、世界律、世界損傷、実効世界再生、戦闘勝者、神の選定者、解放、抑制という独自概念が多い。

すべてを開始前に説明すると、ルールを理解する前に離脱しやすい。

初回導入は説明書ではなく、CPUとの短い一戦で覚えさせる。

初回は次の三つだけ理解できれば開始できるようにする。

1. 相手の体力を0にすると戦闘では勝てる
2. 世界を壊しすぎると神の評価が下がる
3. カードには強く使う「解放」と安全に使う「抑制」がある

世界律の細部、採点式、破界責任などは、必要になった時点で画面上に説明する。

### 2.3 正式勝者を「神の選定者」とするなら、途中予測が必須

現行方針では神の選定者が正式勝者である。

この設計自体は本作の独自性になるが、結果画面で初めて逆転を知らされると不公平に感じやすい。

そのため、試合中に完全な点数式を見せる必要はないが、少なくとも次を常時または行動前に確認できるようにする。

- 現在、自分が選定優勢か劣勢か
- このカードを解放した場合、評価が上がるか下がるか
- 世界崩壊時に自分が不利になる可能性

「なぜ負けたか」だけでなく、「負ける可能性を事前に知ることができたか」を受入条件に追加する。

### 2.4 36種類と48種類の役割をさらに分ける

現行計画では36種類を完成品質を小さく切り出した版、48種類を限定公開候補としている。

ただし、カード数そのものを公開条件にすると、内容の薄いカードを増やす方向へ進みやすい。

今後はカード枚数ではなく「成立している判断の種類」を公開条件の中心にする。

36種類段階では、少なくとも次の判断が複数のカードで成立していることを確認する。

- 今すぐ攻撃するか世界を守るか
- 解放するか抑制するか
- 相手の世界損傷を利用するか
- 世界律の境界を今越えるか、越えないか
- 防御カードを今使うか温存するか

48種類は、これらの判断へ別解を増やす場合にだけ追加する。

### 2.5 再戦理由は機能追加より試合差分を優先する

図鑑、共有、称号は再戦を助けるが、それだけではゲームそのものの再戦理由にならない。

最優先は「次の試合では違う判断が起きる」ことである。

再戦理由の優先順位を次の順にする。

1. 世界律が変わる
2. 配られるカードと相手の判断が変わる
3. 同じカードでも解放・抑制の選択が変わる
4. 結果称号、共有、図鑑

図鑑や共有機能は、中心ルールが成立してから追加する。

## 3. 商品として追加すべき測定項目

現行計画の勝敗分布だけでは、ゲームが遊ばれているか判断できない。

限定公開では、個人アカウントを必須にせず、匿名の集計で次を確認できる設計を推奨する。

- ゲーム開始画面から一戦開始まで到達した割合
- 一戦を最後まで完了した割合
- 終了後に同じ相手と再戦した割合
- CPU練習後に対人戦へ進んだ割合
- 降参・切断・時間切れの割合

数値目標は試作前に厳密固定しない。最初の20〜50試合を基準値として取り、その後に目標を設定する。

## 4. 初回公開範囲の見直し

初回限定公開で必須とするものは、次へ絞る。

- CPU練習
- 合言葉による1対1
- 世界律
- 戦闘勝者と神の選定者
- 再戦
- 最低限の結果説明

初回限定公開では、次を必須にしない。

- 公開マッチング
- レート
- ランキング
- カード収集
- 育成
- 大規模な図鑑
- 多人数戦

この順序は現行計画と整合しており、維持する。

## 5. 公開を止める条件

次のいずれかが残る場合、限定公開へ進めない。

### P0：企画上の停止条件

- 世界損傷を無視して攻撃し続ける戦い方が明確に最適
- 世界回復だけを繰り返す戦い方が明確に最適
- 戦闘勝者と神の選定者が違う理由を多くの試遊者が理解できない
- 初心者が一戦目で何を目指すゲームか説明できない

### P1：商品上の停止条件

- 試合時間が長く、10分を大きく超える試合が頻発する
- 待ち時間が遊んでいる時間より目立つ
- 一戦後に「もう一戦」の理由がルール側にない
- 世界律が試合中のカード選択をほとんど変えない

## 6. 段階別の判断

### 6.1 12種類

目的は面白さの証明だけとする。

見た目やオンライン通信より先に、世界を壊すか守るかで本当に迷うかを確認する。

ここで迷いが起きなければ、カードを24種類へ増やさず、中心ルールへ戻る。

### 6.2 24種類

処理順、手札事故、戦術の偏り、採点の納得感を確認する。

この段階でCPUまたは同一端末による反復試験が安定しない場合、オンラインへ進まない。

### 6.3 36種類

「完成品質を小さく切り出した版」とする考えは維持する。

ただし完成条件は枚数ではなく、初回導入、試合時間、判断の多様性、結果説明、iPhone操作を含めて判定する。

### 6.4 48種類

36種類で再戦時の変化が不足した場合にだけ増やす。

36種類で十分な試合差分が出るなら、48種類を公開前必須条件にはしない。

## 7. 今後の優先順位

プロダクトマネージャー視点では、今後の順序を次とする。

1. 12種類のカードと世界律で中心の迷いを証明する
2. 一戦の時間と待ち時間を測れるようにする
3. 初回CPU練習の導線を設計する
4. 神の選定結果を途中で予測できる表示を設計する
5. 24種類へ拡張し、戦術の偏りを確認する
6. 36種類段階で限定公開の可否を判断する
7. 必要な場合だけ48種類へ増やす

## 8. 次工程への申し送り

ゲームクリエイター視点では、次を重点的に検証する。

- 世界を壊したとき、数値ではなく感情として罪悪感や怖さが生まれるか
- 世界を守ったとき、単なる点数稼ぎではなく英雄的な行動に見えるか
- 戦闘勝者と神の選定者が分かれる瞬間を、作品の見せ場として成立させられるか
- 約7分の中で、序盤・中盤・終盤の変化を作れるか
- 世界律が毎試合の物語を変える装置として見えるか

## 9. レビュー判定

**判定：条件付きで次工程へ進行可。**

企画の中心を作り直す必要はない。

ただし、次の四点を今後の現行計画へ反映する。

- 約7分を固定値ではなく検証目標として扱う
- 初回説明をCPU短縮戦へ寄せる
- 神の選定結果を試合中に予測できるようにする
- 48種類を限定公開の絶対条件にしない
