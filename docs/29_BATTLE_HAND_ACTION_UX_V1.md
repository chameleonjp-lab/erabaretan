# エラバレタン：P3-02 手札・行動UX V1

- 文書状態：P3-02 実装・自動検証記録
- 更新日：2026-08-16
- 対象rulesetId：`ruleset.alpha-12.v1`
- 対象engineVersion：`game-core.alpha-12.v1`

## 1. 目的

P3-01で操作できるようになった手札を、初めて遊ぶ人でも読み取れる表示へ整える。ルール計算は変更せず、既存のproduction previewを行動ボタンの説明へ使う。

## 2. 変更内容

- カードIDを前面に出さず、カード名・役割・効果を日本語で表示
- 解放・抑制・応答・捨てて終了ごとに、行動の要点をボタンの横へ表示
- 攻撃カードは「相手へ」「世界へ」を同じ行で示す
- 攻撃など応答で結果が変わる行動は「応答で変化」と表示
- 世界へ大きな損傷を与える解放だけ、実行前に確認画面を挟む
- 確認画面では、カードの意味、行動内容、実行前の予測をまとめて示す
- 確認中は他の手札操作を押せない

通常のカード操作には毎回確認を出さない。確認を出す対象は、初期12種類で世界損傷7を直接与える「星砕き」の解放に限定する。世界損傷2の行動は、カード説明と行動欄で示す。

## 3. 秘密情報と決定性

表示する予測は`previewAlpha12Command`を通し、相手の防御手札や山札順を表示しない。攻撃のように応答で変わる行動は、確定値として扱わず「応答で変化」と表示する。

カード説明は現在操作しているプレイヤーの手札にだけ表示する。フィールドの追加効果と、傷痕への審罰の発動条件も表示する。相手の手札を画面へ渡す処理は追加していない。

## 4. 検証

`tests/web/p3-01-battle-shell.test.mjs`に、次を追加した。

- カード説明と行動説明の文言
- 世界損傷7の解放だけ確認対象になること
- production previewが攻撃を部分予測として返すこと
- preview前後で元の状態が変わらないこと
- 確認ボタン、カード説明、確認取消、応答・再戦の画面入口、44px以上の操作領域を持つ画面構造

型検査、Webビルド、既存game-core/content試験、P3-01/P3-02試験を通し、全104件が成功した。静的HTTP配信で`web/index.html`と生成main.jsの200応答も確認した。

この環境では実ブラウザとiPhone実機の手動確認は行っていない。公開前に、カード説明が320px/390px縦画面で読めることと、確認画面から実行・取消が迷わず行えることを確認する。
