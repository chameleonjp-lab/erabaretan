## 5. 商品として固定した判断

### 5.1 約束

> 約7分で、相手を倒すか世界を守るかを迫られ、最後に神から戦い方そのものを査定される対戦カードゲーム。

単に「ゴッドフィールドに世界ゲージを足した作品」にはしない。

### 5.2 二つの結果

結果画面では、次の二つを分けて表示する。

- **戦闘勝者**：最後まで生存した者、または戦闘上の優位者
- **神の選定者**：生存、世界損傷、世界再生を合算した総合評価1位

本作の正式な勝者は「神の選定者」とする。

ただし、生存者と選定者が異なる試合は例外的な見せ場とし、全試合の中心にはしない。

### 5.3 カードの二軸

カードには、次の二つを別々に持たせる。

- 戦闘上の役割：攻撃、防御、介入、フィールド
- 世界への影響：再生、中立、損傷

### 5.4 内容量

- 12種類：面白さの最小確認
- 24種類：オフライン試作
- 36種類：完成品質を小さく切り出した版
- 48種類：限定公開候補

24種類を、そのまま一般公開版の完成内容とはみなさない。

## 6. 技術面で固定した判断

### 6.1 実装順

通信機能から作らない。

最初に12種類のカード、状態遷移、効果命令、乱数、世界律、ゴールデン試合を固定する。

その後、純粋なルール基盤、同一端末対戦、CPU、自動対戦、完成品質確認、オンライン対戦の順に進む。

### 6.2 決定的なルール処理

同じルール一式、乱数の種、操作列から、ブラウザ、Node.js、Workersで同じ結果を作る。

ゲーム結果へ`Math.random()`、端末時刻、描画フレーム、通信到着時刻を混ぜない。

### 6.3 カード効果

カードデータへ自由なJavaScriptを入れない。

型で制限した共通効果命令を組み合わせる。

最初の12種類では、カード専用処理を使わない。

### 6.4 正しい状態

オンラインでは、1操作ごとに次を一体で保存する。

- 新しい状態のスナップショット
- 受理した操作
- 発生したイベント
- 次の期限
- 状態の版番号

保存完了後に、各プレイヤーへ結果を通知する。

### 6.5 秘密情報

完全な試合状態を全員へ送って画面側で隠す方法は禁止する。

対戦管理側で、プレイヤーごとの公開状態を作る。

相手の手札、山札順、未使用乱数、再接続情報を送らない。

### 6.6 オンライン構成

正式オンライン版は、次を第一候補とする。

- Workers Static AssetsとWorkerを一体で配信
- 1対戦部屋につき1Durable Object
- SQLite-backed storage
- Hibernation WebSocket API

P2Pは、正式結果を残さない研究対象として後回しにする。

### 6.7 更新互換

試合開始時に`rulesetId`と`catalogHash`を固定する。

新しい配信へ更新しても、進行中試合へ新しいカード数値を上書きしない。

配信物には、少なくとも現在版と直前版のルール処理を含める。

### 6.8 終了種別

次を区別する。

```text
NORMAL
SURRENDER
DISCONNECT_FORFEIT
SERVER_ABORT
INVALID_MATCH
```

降参、切断敗北、サーバー中止、不正な試合停止を、通常の神評価やカード勝率へ混ぜない。

## 7. 初期ルールで固定した判断

- カード補充は手番開始時に行う。
- 先攻は最初の手番だけ補充しない。
- 初期手札は7枚、手札上限は9枚。
- 一手番に使う通常カードは1枚。
- 一つの攻撃に対する防御・反応は最大1枚。
- 反射への再反射は入れない。
- 世界境界75、50、25を一度に越えた場合は、75、50、25の順に一度ずつ処理する。
- 世界0や体力0になっても、現在の必須効果を最後まで処理してから終了判定する。
- 山札が空になっても捨て札を戻さない。
- 時間切れで世界損傷カードを自動解放しない。

この内容を変える場合は、新しい`rulesetId`を作る。

## 8. 直近の作業

コード作成前に、次を一つの仕様作業として完成させる。

1. 初期12種類のカード定義と山札枚数
2. 最初の世界律
3. 共通効果命令の正式な型
4. 決定的乱数生成器と固定試験値
5. ゴールデン試合3件
6. 各試合の最終状態ハッシュ

これらが確定した後、12種類の純粋なルール基盤を実装する。

オンライン対戦は、商品計画V2と技術設計V3の品質門を満たすまで着手しない。

## 9. 公開判断

次を満たすまで、公開マッチング、レート、ランキングを追加しない。

- 初心者が最終評価を予測できる
- 世界への影響が実際のカード選択を変える
- 生存者と選定者が違う結果に納得できる
- 回復だけ、破壊だけの単純な戦い方が最適にならない
- iPhoneで一試合を安定して完了できる
- 同じ入力から同じ結果を再現できる
- 秘密情報がクライアントへ漏れない
- 切断、再送、再読み込みで対戦状態が壊れない
- 配信更新後も進行中試合が開始時のルールで終わる
- 1試合の通信、保存、実行量を把握している
